Google Calendar 3단계 연동: .ics 업로드 · 부가기능(Add-on) · 사내 마운트

20-Year Engineer Perspective #1
엔지니어링 통찰 [3-2]: 입력 소스가 Google Calendar이기 때문에 표준 RFC 5545 iCalendar(VEVENT) 규격과 Google Workspace Add-on 생태계를 100% 활용할 수 있습니다. 초기에는 .ics 파일 업로드로 가볍게 시작하고, 이후 부가기능 설치를 통해 캘린더 안에서 가족과 양방향으로 소통하는 구조로 진화합니다.
1️⃣ Google Calendar 연동 3가지 모드 (도입 난이도순 단계별 지원)
Mode A · 무인증 즉시 시작

📂 내보내기(.ics) 파일 업로드

구글 캘린더 [설정 → 내보내기]로 받은 .ics 파일을 업로드하면 DTSTART, DTEND, SUMMARY, LOCATION을 파싱해 1초 만에 월간 스케줄을 구성합니다.

Mode B · 무조작 자동 수집

🔗 비공개 iCal / Webhook

캘린더의 비공개 iCal URL(basic.ics) 또는 Calendar API events.watch 웹훅을 연결하면 승무원이 폰 캘린더에 일정을 적는 즉시 서버에 자동 반영됩니다.

Mode C · 양방향 커뮤니케이션

🧩 Google Calendar 부가기능

구글 캘린더 우측 사이드바 Add-on(Apps Script / CardService)을 설치해 일정 클릭만으로 등하원 담당을 지정하고 연착 시 일정 시간을 역으로 자동 패치합니다.

2️⃣ 양방향 캘린더 파이프라인 (승무원 Google Calendar ↔ CrewPing ↔ 파트너 사내 Calendar)
① 승무원 Google Calendar • 비행/스탠바이 일정 등록
• Add-on 사이드바에서 등원(배우자)/하원(부모님) 선택
⇄
② CrewPing 코어 서버 • 편명 정규식 추출(KE914)
• 공공API 연착 감지 시 구글캘린더 events.patch 역반영

SECTION 05 · CORE ADVANCEMENT [3-5]

승무원 동선 프라이버시 보안: Signed Token & 4-Role 맞춤 뷰

20-Year Engineer Perspective #2
보안 핵심 원칙 [3-5]: Google Calendar를 '전체 공개'로 전환해 외부에 공유하는 방식은 검색 노출 및 링크 유출 시 승무원의 자택 부재 시간·해외 체류 동선이 노출되는 심각한 보안 사고로 이어집니다. CrewPing은 캘린더를 비공개로 유지한 채 서명된 가족 전용 토큰과 4-Role 맞춤 뷰만 안전하게 노출합니다.
1️⃣ Zero-Trust 가족 공유 보안 아키텍처
보안 계층 1

🔑 역할별 HMAC 서명 링크

단순 일련번호 URL이 아닌 CrewID + Role + Expiry + Nonce를 서버 비밀키로 서명한 토큰 URL을 구성원별로 각각 발급합니다.

보안 계층 2

📱 최초 접속 기기 바인딩

부모님 스마트폰에서 초대 링크를 처음 열면 HttpOnly Secure Cookie에 기기 지문을 바인딩하여, 타인이 링크만 복사해 열람하는 것을 차단합니다.

보안 계층 3

🛡️ 비공개 원본 보호 & 즉시 폐기

원본 Google Calendar의 비공개 키는 서버 금고(Secret Store)에만 암호화 보관하며, 원클릭 토큰 회전(Rotation)으로 유출 의심 시 즉시 무효화합니다.

2️⃣ 단일 캘린더 데이터(SSOT) 기반 4-Role 맞춤형 화면(Role-Based View) 분리
